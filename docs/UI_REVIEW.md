# 工作台 UI 翻新建议

## 1.7.0 边栏修改与新的体验结论（2026-11-15）

本节依据当前源码、1440×960/900×800/700×800合成项目实测；下方原1.6.0审查保留为历史基线，其“固定210px”等描述不再代表当前版本。

本轮已实现：两侧分隔线拖动、范围约束、本机宽度记忆、双击/键盘复位与Esc取消；常用属性13px、次要步骤信息12px；内容/排版优先，低频分组折叠并保留展开选择；出现退场与动效分离；编辑选项收起；删除重复小字说明和一组重复文字对齐按钮。锁定和演示隐藏状态保留在折叠标题上。导出不携带本机布局，独立HTML恢复完整编辑能力。

### 下一轮优先考虑的五件事

1. **让步骤可看见（高优先级）。** 当前步骤卡片主要是名称、数量和时间，用户难以判断“这一屏到底展示什么”。建议加入实际播放状态缩略图，包含此前保留内容与退场结果；选中、临时聚焦和播放继续区分。验收时检查缩略图与真实演示的一致性，不能只截该步新对象。
2. **明确页面与长画布的关系（高优先级）。** 当前步骤是在同一画布上累积显隐与移动镜头；熟悉PPT的人容易以为新步骤就是空白新页。建议提供“标准页面汇报”和“长画布讲解”的创建选项，前者以16:9页面框/明确页面边界组织内容；已有长画布项目保持兼容。这涉及数据与交互设计，尚未实现，不宜仅把步骤改名为幻灯片。
3. **减少画布遮挡和重复入口（中优先级）。** 文本浮动条、底部工具、横向导航同时占用画布；700px窗口下右侧覆盖栏会挡住文字条。建议文本条自动避开所选内容与边缘，常用文字控件保持一个主要入口；底部优先拖动、缩放、适应，其余归更多工具。验收应覆盖边缘对象、低缩放和窄窗口。
4. **统一时间与预览入口（中优先级）。** 单对象和步骤停留使用毫秒，动效编排使用秒。建议界面统一为秒，数据仍保持毫秒，标明自动播放停留与动画时长的区别；“预览本步”和“从本步演示”用途清楚。需要换算与保存往返测试，不能只更换标签。
5. **收整顶部并持续显示保存状态（中优先级）。** 当前新建、导入、项目、导出占据多个同级按钮，小于1100px时保存状态隐藏。建议合为文件菜单，保留首页、项目名、撤销/重做、搜索与演示；窄屏也能直接发现保存中/失败状态。文件菜单必须可键盘打开，不依赖纯图标猜测。

本轮没有实现以上五项大改，也没有进行真实用户可用性访谈或大项目性能测试；结论是当前界面与实现的体验审查。优先建议先做步骤缩略图，再确认是否要增加标准页面模式。

复核证据：docs/qa/sidebar-before.png、sidebar-after.png、sidebar-narrow.png、sidebar-result.json。边栏和属性改动不改变project schemaVersion、出现/退场规则或图层编辑隐藏语义。

审查日期：2026-11-15。基于当前源码、合成项目界面与欢迎页实测。目标：明确分区、减少常驻说明、采用简约商务风；保留组件编辑和逐步演示的效率。

## 本轮已落实

- 桌面启动改为窗口最大化，保留原生标题栏及最小化、还原、关闭按钮。不再主动进入独占全屏；浏览器页面也不再自动请求全屏。原生最大化与独占全屏是两个独立操作，已按 [Electron窗口接口](https://www.electronjs.org/docs/latest/api/browser-window#winmaximize) 核对。
- 桌面启动先到欢迎页：新建汇报、导入项目、最近项目、全部项目和帮助。新建为真正空白项目，无自动示例导入。已有项目不删除、不改造成模板。
- 欢迎页不播放教程、不出现“即将开放”占位。后续引导应通过独立入口加入，不能妨碍继续最近项目。
- 桌面编辑栏移除重复的全屏入口。删除组件区介绍段、项目数据介绍段、镜头设置引言和底部常驻操作说明；临时聚焦的解释转为按钮提示。
- 欢迎页采用灰白底、深灰正文、少量深蓝操作色、细分隔线、列表式最近项目；无渐变、装饰性光效、宣传口号和功能卡片墙。

以下为后续改版建议，尚未整体实施。

## 1. 顶部：只处理项目和全局操作

现状：项目入口、新建、导入、撤销、导出、演示、搜索横排，按钮视觉权重接近。项目名和保存状态容易被淹没。

建议：左侧为首页、项目名与保存状态；项目名旁的菜单收纳重命名、导入导出等文件操作。中间保留撤销、重做。右侧放搜索和主按钮“演示”。搜索支持现有快捷键，入口不必写出操作说明。新建、文件管理可从首页和文件菜单进入。

验收：1000px宽窗口下项目名仍可辨识，不因长标题挤掉演示按钮；保存失败显示明确文字，不仅靠颜色提示。

## 2. 左侧：组件、图层、步骤各自完成一类任务

现状：210px侧栏顶部长期显示动效编排、拖入连线、导图快捷键和编号跳转，切换标签后仍占同样空间。步骤栏还叠有编号输入、说明和创建按钮。

建议：保留“组件／图层／步骤”三个标签。组件区只放基础组件与个人组件；图层区只放筛选和对象树；步骤区只放编号定位、步骤列表和新建步骤。动效编排放步骤区或对应动作入口。“拖入连线”“导图快捷键”属于编辑偏好，移入画布工具的更多菜单，开启后才显示紧凑状态。

步骤卡片以编号、名称为主，数量与停留时间为次。焦点、播放、更多操作在选中行或键盘聚焦时出现；不能只支持鼠标悬停。保留单击选择、双击聚焦、Ctrl+J定位。

验收：标签切换后前屏显示对应的主要内容；编号选择、搜索、折叠、隐藏不因精简而增加绕行。

## 3. 中央：把编辑工具与文档内容分清

现状：画布底部存在操作条、横向导航条和页面状态栏；文本工具悬浮在内容旁，有遮挡风险。

建议：画布底部只保留拖动、缩放比例、适应视野。全选、网格、辅助设置移入菜单或使用现有快捷键。水平导航贴边处理，避免另一条悬浮面板。文本工具只在编辑文字时出现，靠近选区但避开内容；移动组件时不显示字体控件。

选中框和连接点应保留清晰差异。编辑器换色不应改用户画布背景、文本颜色、图片或组件主题。

验收：选择与拖动时无面板遮住主要操作点；低缩放下手柄仍可点中；键盘用户能访问所有被收起的命令。

## 4. 右侧：按所选对象提供设置，常用项先出现

现状：名称、外观、对齐、文字、排版、图层、动效与交互纵向累积。多个区域重复放复制、编辑等按钮，低频设置和高频设置占相同空间。

建议：顶部固定显示对象名称或“已选N项”。下方按“内容／外观／动效／交互”组织，优先展开对应类型的常用项；高级阴影、细节描边等可折叠。批量选择只显示可共同修改的字段。组件复制、置顶、置底优先留在上下文工具或右键菜单，减少重复。

步骤属性继续区分三种含义：镜头模式为持久设置，聚焦为临时查看，播放为演示入口。自动取景与记录镜头使用成组选择，当前模式可直接识别。

验收：常用文字、填色、步骤归属不需滚动多屏；切换对象不会丢失输入；“编辑隐藏”和“演示隐藏”仍能分清。

## 5. 动效：保留图像联动，降低表单密度

现状：左画布右列表已改善对象辨认，但每行重复字段名称、单位和多个小按钮，长列表仍密集。

建议：列表首列显示对象缩略或类型图标与名称，选中动作高亮；效果、开始方式和时长按列对齐。单位统一在列头标注，避免每行重复。“间隔”和低频操作可在选中动作的详细区展开。编号切步、预览、返回原动作继续保留。

不将当前单次入场编排包装成复杂时间轴；现阶段无需增加空轨道、装饰性刻度或未经实现的关键帧入口。

验收：选中动作与画布框对应；预览返回仍恢复步骤、动作和滚动位置；列表密度提高后，输入框不小于可操作尺寸。

## 6. 文字：删除介绍，保留决定操作的状态

直接删除：重复解释“所有内容都可编辑”的段落、描述显而易见按钮用途的文字、底部长期滚动式教程、产品式宣传语。

移至提示或帮助：双击进入组合、Alt临时关闭吸附、自由线端点拖动、编号输入格式等技巧。提示也应可通过键盘焦点或帮助入口获取，不能成为发现核心功能的唯一方式。

继续显示：保存失败、只读或锁定、当前编辑隐藏、部分选中、目标不存在、非法编号、即将删除等会影响用户判断的信息。

文案尽量使用动作和对象，例如“定位”“预览”“已保存”“隐藏3项”。解释要解决当前疑问，不重复描述产品能力。

## 7. 统一视觉规范

- 灰白背景、深灰正文、一个深蓝强调色；红色仅用于错误或删除。选中、悬停、禁用三种状态应明确。
- 常用文字建议13–14px，标题15–16px，次要元信息12px；减少当前10–11px常驻说明。不能通过把文字变灰变小来“简洁化”。
- 常规控件高度32px，间距以8/12/16px为基础，圆角4–6px。使用一致的线性SVG图标，逐步替换形态不一致的字符图标。
- 用留白、对齐与细分隔线区分区域；仅弹窗与必要悬浮层使用轻阴影。避免每个功能都包一张卡片。
- 原生窗口栏保留；不自制一套外观相似、行为却不同的窗口按钮。

## 建议实施顺序

1. 统一顶部与左侧功能归属，确定唯一的主要入口。
2. 收整右侧属性与画布工具，删去重复说明。
3. 统一字号、间距、图标及状态色。
4. 调整动效列表密度，完成键盘、长名称、小窗口和隐藏状态回归。
